# AgriDrone AutoMap — Phase 2 Open Design Questions

## 1. Overview & Governance of Design Decisions

This document records all unresolved UI/UX design questions, aesthetic trade-offs, and operational interaction patterns identified during Phase 2. These questions require stakeholder review and confirmation before final component implementation in future phases.

---

## 2. Design Question Registry

### Question 01: Top Navigation Bar vs. Collapsible Left Sidebar on Desktop
- **Context**: The primary reference template (`drone-main`) utilizes a clean, sticky top navigation header (`h-16`, `border-b`). The desktop codebase (`dron`) utilizes a dual-layout combining a top header with a collapsible left sidebar (`w-64`).
- **Options**:
  1. *Option A (Reference Standard)*: Top horizontal navigation bar. Leaves 100% of horizontal screen width for wide data tables and the MapLibre map canvas.
  2. *Option B (Collapsible Sidebar)*: Left vertical sidebar with icon + label stack. Collapses to icons on hover or toggle.
- **Impact**: Affects page container width calculation and mobile drawer transition.
- **Recommendation**: Maintain Option A (Top Bar) as the baseline for the Five-Page architecture to maximize map viewing area.

---

### Question 02: Default Scientific Vegetation Index Color Palette
- **Context**: On Page 3 (Algorithms) and Page 4 (Farmer Portal), vegetation index rasters (NDVI, NDRE) are colorized.
- **Options**:
  1. *Option A (5-Class Agronomic RdYlGn)*: Standard agricultural convention: Red (Bare/Stressed) $\rightarrow$ Yellow $\rightarrow$ Green (Dense Canopy). Intuitive for farmers, but red/green can pose accessibility challenges for deuteranopia.
  2. *Option B (Continuous Viridis)*: Perceptually uniform scientific standard: Purple $\rightarrow$ Teal $\rightarrow$ Yellow. 100% accessible to color-blind users, but less familiar to conventional growers.
  3. *Option C (Dual-Mode User Toggle)*: Default to 5-Class Agronomic with an immediate high-contrast / color-blind toggle in the map legend.
- **Impact**: Determines default raster colormap lookup tables (LUT) generated by GDAL/Rasterio.
- **Recommendation**: Option C (Dual-Mode with default Agronomic and one-click accessibility toggle).

---

### Question 03: Mobile Map Controls — Bottom Sheet Drawer vs. Overlay Toolbar
- **Context**: On mobile viewports ($< 768\text{ px}$), the MapLibre canvas on Page 4 needs to display active layers, legends, opacity sliders, and pixel values without obscuring the field imagery.
- **Options**:
  1. *Option A (Floating Bottom Sheet Drawer)*: Map occupies full viewport height. A compact grab bar at the bottom expands upward upon tapping, displaying legends and layer switches.
  2. *Option B (Top Floating Overlay Toolbar)*: Semi-transparent icon buttons anchored to the top-right corner of the map canvas, opening modal flyouts.
- **Impact**: Mobile map navigation ergonomics and gesture conflicts with map panning.
- **Recommendation**: Option A (Bottom Sheet Drawer). It adheres to modern mobile GIS conventions and prevents accidental layer switching while panning the map.

---

### Question 04: White-Labeling & Farm Entity Branding
- **Context**: The reference template (`drone-main`) included a `BrandingSettings.tsx` component allowing corporate agricultural clients to upload custom logos and customize accent colors.
- **Options**:
  1. *Option A (Single Unified Platform Brand)*: Fixed "AgriDrone AutoMap" branding with emerald/forest color scheme across all users.
  2. *Option B (Tenant White-Labeling)*: Allow enterprise farm administrators to display their own farm logo and company name in the farmer portal view.
- **Impact**: Multi-tenant database schema complexity and CSS variable injection (`--client-accent`).
- **Recommendation**: Defer full white-labeling to post-launch roadmap; maintain unified AgriDrone AutoMap branding for the 5-page MVP.

---

### Question 05: Multi-Lingual Regional Localization Support
- **Context**: Inspection of the local `dron` codebase revealed support for regional agricultural languages (e.g., English and Marathi with `font-noto-devanagari` support) to serve regional farm communities.
- **Options**:
  1. *Option A (English Only for MVP)*: Build all 5 pages strictly in English.
  2. *Option B (i18n Localization Scaffold)*: Scaffold frontend text strings using an internationalization library (e.g. `next-intl` or lightweight dictionary JSONs) allowing future language switching.
- **Impact**: Frontend bundle size, component typography font loading, and translation overhead.
- **Recommendation**: Author all Phase 2 prototype text in clear English while avoiding hardcoded text in core GIS icons and badges to facilitate future i18n localization.

---

### Question 06: Dark Mode Theme Support
- **Context**: The reference template is exclusively a clean, high-contrast light theme (`#f8fafc` canvas with white cards). Some GIS technicians prefer dark mode for prolonged night-time map analysis.
- **Options**:
  1. *Option A (Light Mode Only)*: Follow the reference template 100% without dark mode overhead.
  2. *Option B (Dark Theme Extension)*: Add a dark mode toggle utilizing Tailwind's `dark:` classes (`slate-900` surfaces).
- **Impact**: Styling overhead and potential contrast degradation on false-color agricultural maps.
- **Recommendation**: Maintain Option A (Light Mode) for Phase 2 prototype to preserve reference fidelity.
